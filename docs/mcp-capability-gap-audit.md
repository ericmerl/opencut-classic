# OpenCut Classic MCP capability-gap audit and completion requirements

Audit date: 2026-09-02
Revised: 2026-09-02 after adversarial specification review and owner decisions (see `Review corrections and owner decisions`)
Audited branch: `codex/issue-1-mcp-editor-bridge`
Audited commit: `54cd0df8` (file-and-line citations are verified to lie within the cited files at this commit; citations into uncommitted worktree files are marked as such)

Deployment context: a local installation on one Windows PC, personal use only, never hosted or offered to others, operated by agents. One editor per MCP instance; concurrency is achieved by running additional MCP instances with their own bridge port, browser profile, and state directory. Requirements that exist only for hosted or multi-user service deployment are excluded from production parity.

This tracked document is the current source-backed requirements baseline for completing the OpenCut Classic MCP. It replaces historical gap assumptions with the behavior present at the audited commit. The evidence boundary is the registered MCP tool surface, input schemas, browser bridge request union, automation read and write contracts, native project and timeline models, commands and managers, renderer, export pipeline, and provider adapters in this checkout. Simple Media workflow requirements come from the canonical `opencut-editing` and `capcut-editing` skills and their MCP execution contract.

## Classification

- **Fully supported**: callable through MCP on a configured checkout, persisted, readable, and covered by a real implementation path.
- **Partially supported**: useful MCP behavior exists, but the requested workflow is incomplete or lacks safe readback, control, fidelity, or lifecycle behavior.
- **Provider-dependent**: MCP plumbing exists, but a fresh checkout cannot execute the capability without a separately configured command or model provider.
- **Unsupported by MCP but present in OpenCut**: OpenCut has the required native state, manager, command, or renderer behavior, but MCP cannot operate it.
- **Unsupported by both MCP and OpenCut**: neither MCP nor the current native model, editor, renderer, provider bundle, or infrastructure implements the required behavior.
- **Optional future enhancement**: outside baseline production parity and not required by a named current Simple Media workflow.

## Requirement-record conventions

Every incomplete matrix row is a requirements record. Its third column states the current implementation, the exact missing behavior, and current code evidence. Its fourth column states the required work layer, the affected workflow or operational outcome, objective acceptance criteria, and production criticality. Section order and the final dependency map define recommended implementation order. When a row names a more specific dependency, that dependency takes precedence. A tool registration, protocol shape, fixture, configured external command, or renderer code path is not classified as fully supported unless the end-to-end behavior is callable, persistent where required, and readable or verifiable.

### Owner decisions (2026-09-02)

1. Bundled background removal, edge refinement, temporal stabilization, and repair paint are outside the parity definition and form the first post-parity project. Precomputed matte attachment remains required.
2. Chroma key and track mattes are production-critical at low priority, scheduled last.
3. Nested-clip editing, shot detection, drift/timecode/multicamera sync, and multicam are optional.
4. Redo/checkpoints, speed ramps and reverse/freeze, and running cancellation are required; insert/overwrite/lift/extract and advanced curve editing are optional for the first release.
5. Named-effect reference clips and tolerances are low priority but must be recorded in the row before implementation starts.
6. Fonts are bundled locally with no run-time third-party fetch. Owner decision 2026-09-04: the bundled set is TikTok Sans and Montserrat (SIL Open Font License, from google/fonts), pinned by SHA-256 in `apps/web/src/fonts/bundled-fonts.ts`; no commercial face is bundled.
7. Delivery formats are MP4 and WebM only.
8. Rendering determinism policy and AI model selection are deferred; AI features are low priority.
9. Multiple jobs are wanted. One editor per MCP instance; parallelism by running more instances. Retention is 90 days.
10. Protocol v1 mutation is disabled by default (implemented 2026-09-03).
11. Human review of the final export is required for watermark and QC sign-off.
12. The project ID is included in canonical projection version 2.
13. No allowlisted-folder policy; the machine is isolated and single-user. The protections against the agent's own mistakes remain: no implicit remote fetch from project state, serve the exact bytes that were hashed, never overwrite an existing export.
14. Windows only. Starting the web editor by hand before MCP is acceptable; the health response must say plainly when the editor is not reachable.

### Requirements removed by the deployment context

Browser-independent rendering, MCP stdio authentication, provider sandboxing and filtered environments, private-path redaction, disk quotas and rate limits, atomic retained-runtime promotion, deployment receipts, metrics, multiple editor sessions in one instance, remote ingest, and non-Windows installation are no longer parity requirements. Correctness, evidence, and fault-recovery requirements are unchanged because agents crash, retry, and disconnect regardless of deployment.

Update 2026-09-03 (#19): one SQLite job model now carries export jobs and batch variants, preview ranges, comparisons, transcription, and provider invocations (`qc` and `packaging` are reserved types) in `packages/mcp-server/src/job-store.ts`, with the spec 17.1 fields (identity, type and schema version, project/scene/revision/hash/write-version/save-receipt preconditions, semantic input hash, capability snapshot hash, provider and renderer policy, priority, resource class, concurrency group, schedule, attempt policy, progress units/phase/completed/total/ETA confidence, heartbeat, checkpoints, logs, diagnostics, artifacts, provenance, cancellation request and observation timestamps, terminal state, attachment transaction) and the spec 17.2 states with an explicit legal-transition table, compare-and-set revisions, lease fencing, SQLite immutability triggers, an append-only history table, and per-row checksums. Export jobs run through `export-jobs.ts` on that store and keep their public record shape (the statuses `cancelling`, `blocked`, and `recovery-required` and an `execution` block are additive); pre-#19 JSON job files are imported once. Running cancellation is wired end to end: `opencut_cancel_export_job` or `opencut_cancel_job` marks the row, the export ticket exposes `GET /export/<id>/status`, the browser export polls it every 250 ms and passes `onCancel` to the native exporter, and the job reports `cancelling` until the renderer confirms; a cancelled render never uploads, so no output file exists, and the policy is declared in `opencut_capabilities` under `jobs.exportCancellation`. Restart reconciliation distinguishes a dead worker (dead PID or heartbeat older than 45 s) from a slow observer (fresh heartbeat with an expired lease) and, before requeueing, terminalizes an export whose receipt exists without rerendering, retains an unreceipted output file and moves the job to `recovery-required`, or records an interrupted attempt and requeues within the attempt policy. `opencut_retry_job` retries failed export and provider jobs; `opencut_resolve_job` resolves `recovery-required` jobs as `rerun-as-new-attempt` (quarantining any partial output as `<output>.attemptN.partial`) or `mark-failed`, always preserving attempt history under the same job id. The provider supervisor now runs on the same store (`provider-supervisor-store.ts`, `provider-supervisor-worker.ts`): workers claim with a lease, heartbeat every 5 s, observe cancellation on the next heartbeat, and a dead supervisor leaves `recovery-required` instead of a permanent `unknown`. Inline range previews, comparisons, and transcriptions are mirrored as job rows by `inline-jobs.ts`, so `opencut_list_jobs` and the capability queue state (depth, running job, per-state and per-type counts, recovery-required ids) cover every job type. ## Exact Simple Media workflow gaps

These are the remaining blockers to claiming the canonical OpenCut skill can replace the browser-based CapCut workflow end to end.

1. **Structured review evidence is still missing.** Exact single-frame PNGs, bounded range artifacts, and immutable before/after visual and audio comparisons are now available through MCP; timestamped or regional review annotations remain unavailable.
2. **Dry-run plan evidence is still missing.** Durable cross-tool idempotency and operation history are complete, but MCP cannot yet validate a full plan without mutation or return its deterministic expanded diff, timing consequences, warnings, and cost estimate.
3. **Background removal generation is outside the parity definition (owner decision 2026-09-02).** Attachment of a precomputed matte works and must keep working; generation, edge refinement, temporal correction, and repair are the first post-parity project. Until then the workflow supplies mattes from an external tool.
4. **Subject tracking and cleaned audio are also external command dependencies.** The MCP schemas and application logic are real, but the providers are not bundled or discoverable.
5. **Caption production now covers the main styled-render path.** Cue import, transcription, correction, reusable Rust-owned speaker presets, independent per-line bubbles, word highlighting, caption restructuring, and clean versus burned-in variant rendering work. Bundling the selected fonts remains outstanding.
6. **Named course visual treatments cannot be reproduced exactly.** Film Frame, Play Pendulum, Technicolor Flash, Scanner Bar, Glitch, Chromatic, Dark Night, Mirror, the required body or meme treatments, and exact Pull In, Pull Out, and Swipe Left behaviors are absent.
7. **Audio post is incomplete.** Core levels, ducking, loudness, sync, and replacement audio work, but bundled cleanup, VAD-derived ducking, `Separate Audio > Vocals` style stem isolation, editable EQ/dynamics, and audio QC receipts are absent.
8. **Course retiming cannot be reproduced exactly.** The Montage speed curve, reverse, freeze-frame construction, independent pitch control, frame blending, and optical flow are missing.
9. **Platform variants now use immutable render overlays.** Safe zones, subject-aware focal selection, per-element layout/reframe, track inclusion, captions-on/off and caption restyling/repositioning resolve independently per export without rewriting the source project; batch manifests preserve mixed results (issue #22).
10. **Delivery encodings are MP4 and WebM only (owner decision 2026-09-02).** AVC versus VP9 is controlled and the full probed encoder result is recorded. Colour tagging, profile, pixel format, and the AAC-or-Opus fallback remain host-browser choices rather than request controls.
11. **Delivery handoff is incomplete.** Export receipts and watermark inspection exist, but there is no complete structured QC policy or package manifest containing variants, subtitle sidecars, cover frames, inspection, and hashes.
12. **The runtime is a hidden managed browser, and that is the accepted production renderer (owner decision 2026-09-02).** Capability/build identity reports the selected compositor, declared renderer class, adapter, surface format, pin status, named-font readiness, and artifact/tool identities; preview/export receipts retain a render-environment fingerprint. Fresh-install, instance-N, persistence/recovery, and commit-verified hidden upgrade procedures are documented and scripted. What remains: bundle the selected caption fonts.
13. **Agentic source editing is not semantic.** No persistent transcript, silence, shot, OCR/object index, or reusable editorial decision model exists.

## Definition of production-ready MCP parity

Production-ready parity is reached only when a fresh documented installation on the owner's Windows PC can, without manual browser editing and with the web editor started by hand as the only manual step:

1. Discover editor, renderer, codec, model, provider, font, and build-identity capabilities before work begins.
2. Create or duplicate a project, manage its scenes/tracks/bookmarks/assets, and import source media.
3. Build and revise the required edit with typed, revision-checked, hash-checked, dry-runnable, idempotent operations.
4. Apply the exact realistic filter, named course effects and transitions, per-line caption bubbles, and all required audio, graphics, mask, tracking, reframe, and retime work, and attach a precomputed background-removal matte. Bundled matte generation is not part of parity.
5. Save as a verified no-op when nothing changed, reload, and prove the same canonical content hash.
6. Render exact preview frames, bounded ranges, and before/after comparisons from retained snapshots, and capture structured review annotations.
7. Run long work as durable, cancellable, recoverable jobs with explicit provider/model provenance under one job model.
8. Render platform variants without destructively rewriting the source edit.
9. Validate full decode, video properties, recorded encoder settings, decoded audio, captions/safe zones, watermark evidence with human final review, and requested platform rules.
10. Produce a durable delivery package with hashes, sidecars, preview/QC evidence, inspection status, and an operation trail.
11. Execute preview and export through the hidden managed browser with a pinned compositor backend recorded in every render receipt.

A registered tool, external-command protocol, synthetic fixture, process-memory replay map, opt-in test that is not run by the standard test command, or unverified render path is not sufficient evidence of parity.
